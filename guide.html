Section 1

Prérequis

Pour préparer la clé USB (une seule fois)

  • Un PC sous Linux, Windows ou macOS
  • Une clé USB de 8 Go minimum (16 Go recommandé — pour stocker les rapports)
  • Docker installé et daemon actif (nécessaire pour construire l'ISO personnalisée)
  • L'ISO SystemRescue officielle téléchargée depuis system-rescue.org
  • Ventoy installé sur la clé (ventoy.net — version ≥ 1.0.97)

Pour lancer un diagnostic (sur le PC à diagnostiquer)

  • Accès au BIOS/UEFI pour démarrer sur USB
  • Aucun logiciel supplémentaire — tout est dans l'ISO
  • Secure Boot : doit être désactivé (sinon SystemRescue ne démarre pas)

Données personnelles : le script fonctionne en lecture seule. Il ne modifie aucun fichier sur le PC diagnostiqué. Les rapports sont enregistrés sur la clé USB, jamais sur le disque du client.

Section 2

Préparer la clé USB

1

Installer Ventoy sur la clé

Téléchargez Ventoy et lancez VentoyGUI (Windows/Linux) ou sudo sh Ventoy2Disk.sh -I /dev/sdX. Sélectionnez votre clé et cliquez Install. La clé sera formatée.

Attention : toutes les données de la clé seront effacées. Faites une sauvegarde si nécessaire.

2

Construire l'ISO SystemRescue personnalisée

L'ISO officielle ne contient pas tous les outils (smartmontools, dmidecode, hivex…). Le script de build les intègre automatiquement.

Terminal — depuis le dossier pc-diag/
cd build/ ./build-iso.sh /chemin/vers/systemrescue-11.x-amd64.iso # Génère systemrescue-pcdiag.iso (5-15 min selon connexion)
3

Copier l'ISO sur la clé Ventoy

cp systemrescue-pcdiag.iso /media/$USER/Ventoy/
4

Copier le script et son hash

mkdir -p /media/$USER/Ventoy/outils/ cp pc-diag.sh /media/$USER/Ventoy/outils/ cp pc-diag.sh.sha256 /media/$USER/Ventoy/outils/ # Si config.sh est créé (personnalisation) : cp config.sh /media/$USER/Ventoy/outils/
5

Créer le dossier de rapports

mkdir -p /media/$USER/Ventoy/rapports/

Les rapports HTML seront automatiquement copiés ici après chaque diagnostic.

Section 3

Personnaliser le rapport

Créez un fichier config.sh dans le dossier outils/ de la clé (à côté de pc-diag.sh) :

Ventoy/outils/config.sh
# Nom affiché dans l'en-tête du rapport ORG_NAME="Repair Café Lyon" # Couleur d'accent (hex) — exemple : bleu #1D4ED8, vert #15803D, orange #C2410C ORG_COLOR="#C2410C" # Logo (chemin sur la clé ou URL si réseau dispo) ORG_LOGO="/mnt/ventoy/outils/logo.png" # Contact affiché en pied de page ORG_CONTACT="Repair Café Lyon — contact@repaircafe-lyon.fr"

Format logo : PNG ou JPG, fond transparent recommandé, hauteur idéale 80-120 px. Le logo est redimensionné automatiquement à 40 px de hauteur dans le rapport.

Section 4

Lancer un diagnostic

1

Démarrer sur la clé USB

Branchez la clé, redémarrez le PC et accédez au menu de démarrage (touche F12, F11, Esc ou Del selon le fabricant). Sélectionnez la clé USB.

2

Choisir l'ISO dans Ventoy

Le menu Ventoy s'affiche. Sélectionnez systemrescue-pcdiag.iso et appuyez sur Entrée. Choisissez Boot SystemRescue.

3

Copier et lancer le script

startx # optionnel — ouvre l'interface graphique mkdir -p ~/outils cp /mnt/ventoy/outils/pc-diag.sh ~/outils/ sudo ~/outils/pc-diag.sh

Durée du diagnostic : 3 à 8 minutes selon le matériel. Le script affiche sa progression en temps réel.

4

Récupérer le rapport

À la fin, le rapport HTML est copié automatiquement dans /mnt/ventoy/rapports/rapport_YYYYMMDD_HHMMSS.html. Il s'ouvre aussi dans le navigateur si une interface graphique est active.

Section 5

Lire et remettre le rapport

Le rapport HTML s'ouvre dans n'importe quel navigateur (Firefox, Chrome, Safari). En haut, le tableau de synthèse résume l'état général en 4 compteurs :

3
OK
2
Attention
1
Critique
5
Info

Remettre le rapport au client

Pour générer un PDF : ouvrez le rapport dans Firefox ou Chrome → Ctrl+P → Enregistrer en PDF. La mise en page d'impression est optimisée.

Astuce : Renommez le fichier avec le nom du client avant de lui envoyer — ex. diagnostic-dupont-jean-20260918.pdf.

Section 6

Interpréter chaque module

Cette section explique ce que mesure chaque module, comment lire les résultats et quelle action recommander au client.

[1/11] Outils système prérequis

Ce module vérifie la présence des outils de diagnostic (smartmontools, dmidecode, lm_sensors, etc.) dans l'ISO. S'il affiche OK, tous les tests suivants seront complets.

S'il affiche ATTENTION avec une liste d'outils manquants : vous utilisez l'ISO officielle sans personnalisation. Rebuildez l'ISO avec build-iso.sh pour avoir tous les outils pré-intégrés.

[2/11] Carte mère & BIOS/UEFI identification

Ce que ça mesure : fabricant, modèle, numéro de série, version BIOS, date du BIOS, mode de démarrage (UEFI ou Legacy).

Ce que vous voyezCe que ça signifieAction recommandée
ATTENTION BIOS daté de +5 ansFailles de sécurité connues, incompatibilités matérielles possiblesProposer une mise à jour BIOS (opération avancée)
Mode Legacy/CSMPC ancien ou configuration non optimaleInformer le client — migration UEFI possible si Windows 11 est envisagé
Numéro de série présentGarantie vérifiable sur le site du fabricantIndiquer au client pour suivi SAV
[3/11] Processeur (CPU) performance & température

Ce que ça mesure : modèle, fréquence actuelle/max, nombre de cœurs, température, gouverneur de fréquence.

Ce que vous voyezCe que ça signifieAction recommandée
Température > 80°C au reposPasta thermique dégradée ou ventilateur encrasséNettoyage ventirad + remplacement pasta thermique
Fréquence bloquée bas (throttling)Le CPU se bride pour éviter la surchauffeMême action — nettoyage urgent
Gouverneur powersaveNormal sur laptop, peut limiter les performancesInformer — aucune action requise
[4/11] Mémoire vive (RAM) identification

Ce que ça mesure : capacité totale, nombre de barrettes, fréquence, type (DDR4/DDR5), slots occupés/libres.

Ce que vous voyezCe que ça signifieAction recommandée
4 Go ou moinsInsuffisant pour Windows 11 ou usage courantProposer une extension RAM si slots libres
Slot libre détectéUpgrade possible sans remplacer l'existantMentionner l'opportunité d'upgrade dans le rapport
Fréquence inférieure au max supportéXMP/EXPO non activé dans le BIOSActivation possible dans le BIOS (opération avancée)
[5/11] Test intégrité RAM (rapide) critique si échoue

Ce que ça mesure : test d'écriture/lecture en mémoire via memtester (1 passe sur 256 Mo ou 10% de la RAM). Durée : 30 secondes à 2 minutes.

Si le test échoue (erreurs détectées) : la RAM est défaillante. Cela explique les plantages, les écrans bleus et les corruptions de fichiers. Remplacement de la barrette fautive nécessaire.

Limite : ce test est rapide — une RAM légèrement défaillante peut passer. Si le client se plaint de plantages inexpliqués, recommandez un test RAM complet (Memtest86+ sur une nuit entière).

[6/11] Disques de stockage (SMART + vitesse) module le plus important

Ce que ça mesure : état SMART de chaque disque (HDD/SSD/NVMe), nombre de secteurs défectueux réalloués, heures de fonctionnement, température, vitesse lecture séquentielle.

Indicateur SMARTSeuil d'alerteAction recommandée
Reallocated Sectors Count> 0ATTENTION — surveillance accrue, sauvegarde immédiate
Reallocated Sectors Count> 50CRITIQUE — remplacement disque urgent
Pending Sectors> 0Secteurs en attente de réallocation — risque de perte de données
Power On HoursHDD > 30 000h / SSD > 50 000hFin de vie prévisible — anticiper le remplacement
Vitesse lectureHDD < 80 Mo/s · SSD < 200 Mo/s · NVMe < 1 000 Mo/sDisque dégradé ou mauvais port SATA

Règle pratique : un disque avec des secteurs réalloués n'est pas forcément mort, mais il faut toujours recommander une sauvegarde immédiate. Expliquez au client que ces secteurs sont des "zones abîmées" que le disque a déjà contournées.

[7/11] Carte graphique (GPU) identification & température

Ce que ça mesure : modèle GPU, driver chargé, température (AMD/Intel/NVIDIA), VRAM utilisée/totale (NVIDIA via nvidia-smi).

Ce que vous voyezCe que ça signifieAction recommandée
Température > 85°CGPU en surchauffe — pasta thermique ou ventilateursNettoyage GPU + remplacement pasta si carte dédiée
Driver nouveau au lieu de nvidiaDriver propriétaire non installéInstaller le driver NVIDIA officiel sous Windows/Linux
GPU non détectéCarte dédiée absente ou port PCIe défaillantVérifier la connexion physique de la carte
[8/11] Stress-test CPU (30 secondes) test de charge

Ce que ça mesure : charge tous les cœurs CPU à 100% pendant 30 secondes et relève la température de fin de test. Détecte le thermal throttling sous charge.

RésultatInterprétationAction
Temp finale < 75°CRefroidissement correctAucune action
Temp finale 75–90°CRefroidissement limiteNettoyage préventif recommandé
Temp finale > 90°CSurchauffe confirmée sous charge normaleRemplacement pasta thermique urgent
Fréquence chute pendant le testThermal throttling détectéMême action — le CPU se bride pour survivre
[9/11] Batterie laptops uniquement

Ce que ça mesure : capacité de design (neuf), capacité actuelle (usée), capacité restante (%), nombre de cycles de charge, état ACPI.

Santé batterieInterprétationÀ dire au client
> 80%Batterie en bonne santéAucun problème
50–80%Usure normaleAutonomie réduite — remplacement si gênant
< 50%Batterie fortement dégradéeRemplacement recommandé
État "Unknown" ou "Critical"Cellule défaillante ou capteur mortDiagnostic approfondi ou remplacement

Sur les PC de bureau (pas de batterie) : ce module affiche INFO — Aucune batterie détectée. C'est normal.

[10/11] Réseau, Bluetooth & USB inventaire périphériques

Ce que ça mesure : interfaces réseau détectées (Ethernet, Wi-Fi), état du Bluetooth, contrôleurs USB (USB 2.0/3.x), ports disponibles.

Ce module est principalement informatif. Il permet de :

  • Confirmer que la carte Wi-Fi est reconnue (même sans connexion active)
  • Détecter un contrôleur USB mort (port qui ne détecte rien)
  • Identifier le chipset réseau pour trouver les drivers sous Windows
[11/11] Table des partitions & OS détectés analyse OS

Ce que ça mesure : schéma de partitionnement (MBR/GPT), taille et type de chaque partition, OS détectés (Windows/Linux/macOS), espace libre, état du système Windows (registre offline via hivex).

Ce que vous voyezInterprétationAction
Espace libre < 10% sur C:\Disque système presque pleinNettoyage disque recommandé
Partition de récupération absenteRéinitialisation Windows impossibleMentionner au client
MBR sur un PC UEFIWindows 11 incompatibleConversion GPT possible (diskpart)
Mises à jour manquantes détectéesSystème non à jour via registre offlineInformer le client — lancer Windows Update

Section 7

Cloner la clé pour un autre poste

Pour équiper un deuxième technicien, la méthode la plus rapide est un clone bit-à-bit :

Linux — cloner la clé source vers une nouvelle clé
# Identifier les clés (source = /dev/sdb, destination = /dev/sdc) lsblk # Cloner — adapter les chemins /dev/sdX sudo dd if=/dev/sdb of=/dev/sdc bs=4M status=progress # Durée : 5-15 min selon la taille de la clé

Alternative plus rapide : copiez uniquement les fichiers (ISO + outils + rapports) sur une nouvelle clé déjà équipée de Ventoy. Les deux méthodes fonctionnent.

Section 8

Mettre à jour pc-diag

Si seul le script est mis à jour (pas l'ISO), il suffit de recopier pc-diag.sh et de régénérer le hash :

cp pc-diag.sh /media/$USER/Ventoy/outils/ ./update-hash.sh pc-diag.sh cp pc-diag.sh.sha256 /media/$USER/Ventoy/outils/

L'ISO n'a pas à être reconstruite — seul le script change. Si de nouveaux outils sont ajoutés à build/packages.txt, une reconstruction complète de l'ISO est nécessaire.

Section 9

FAQ dépannage

Le PC ne démarre pas sur la clé USB

Vérifiez que le Secure Boot est désactivé dans le BIOS. Testez une autre touche de menu boot (F12, F11, Esc, Del). Sur certains HP, appuyez sur F9 spécifiquement.

Avertissement "Intégrité du script non vérifiée"

Le fichier pc-diag.sh.sha256 est absent ou ne correspond plus au script. Recopiez le script et relancez update-hash.sh.

Le rapport n'est pas copié sur la clé

Ventoy n'est pas monté sur /mnt/ventoy. Montez-le manuellement : mkdir -p /mnt/ventoy && mount /dev/sda1 /mnt/ventoy (adaptez /dev/sda1). Puis copiez manuellement : cp /root/rapports/*.html /mnt/ventoy/rapports/

Certains modules affichent "outil absent"

Vous utilisez l'ISO officielle sans les paquets intégrés. Rebuildez l'ISO avec build/build-iso.sh. Sur l'ISO officielle, vous pouvez installer temporairement : pacman -Sy smartmontools dmidecode lm_sensors hivex (perdu au redémarrage).

Le test RAM se bloque

Sur une machine avec beaucoup de RAM (> 32 Go) ou très lente, le test peut prendre plusieurs minutes. Si le script semble bloqué après 10 minutes, appuyez sur Ctrl+C — les autres modules continueront. Le rapport sera incomplet pour ce module uniquement.
